# mod-112-program-design-and-org-shape: AI Governance Operating Model and Program Design

This is the level-50 architect's module for standing the AI-governance programme *up as an organisation*. Modules 102–111 authored the design artefacts — control library, policy taxonomy, jurisdiction-reconciled control set, AIMS, risk taxonomy, assurance architecture, evidence architecture, third-party programme, PMS shape, GRC-for-AI reference architecture. This module composes those artefacts into a decision forum (the AI governance council), a seat-level operating model, a hiring plan against real role packets, a cross-audience communications architecture, a change-management plan for policy and standard rollouts, a certifications-portfolio positioning, a standards-community contribution posture, and — closing the module — the boundary specification against the head-of-AI-governance (level 60) and chief-AI-officer (level 70) above. Downstream mod-113 (sector and jurisdiction blueprints) composes with the operating model and hiring plan this module ratifies.

**Estimated effort:** 14 hours

## Learning objectives

- Design the AI governance council — charter, membership, decision authority, escalation ladder, cadence, quorum, minute-keeping — so the council is the single decision forum for enterprise AI risk
- Design the three-lines-of-defense for AI operating model — first line (product / ML / engineering), second line (this architect + governance program + risk function), third line (internal audit / independent AI audit) — with clear RACI at each control
- Author role descriptions that link out to the correct owner packet — `ai-governance-analyst` (level 15), `ai-risk-engineer` (level 25), `ai-evaluation-engineer` (level 35), `ai-eval-engineer` (level 30), `model-evaluation-engineer` (level 30), `agentic-safety-engineer` (level 40), `security-learning` / `ai-infra-security` (level 35), `head-of-ai-governance` (level 60), `chief-ai-officer` (level 70) — so the hiring plan is defensible and each hire has a training track to point at
- Design the cross-audience communications architecture — how the architect writes for CISO / GC / CIO / CFO / CEO / audit committee / regulator / employee / customer audiences — running architecture-review-board sessions, packaging position papers for the head of AI governance to take to regulators, briefing the AI governance council
- Design the change-management plan — how a policy or standard change rolls out across the organisation, communications cadence, training update, exception window
- Position the certifications portfolio — IAPP AIGP (near-universal in senior architect postings), ISO/IEC 42001 Lead Implementer / Lead Auditor, ForHumanity Independent AI Auditor, BABL AI Algorithm Bias Auditor, IAPP CIPP where privacy-adjacent, ISACA CISA / CISM / CRISC where audit / risk adjacent; know which are load-bearing in enterprise hiring versus which are optional signals
- Design the standards-community contribution posture — ISO/IEC JTC 1/SC 42, CEN-CENELEC JTC 21, IEEE 7000-series, NIST public workshops, Frontier Model Forum, Partnership on AI, OECD.AI — enough to represent the enterprise position without needing external counsel to draft
- Cite the boundary to `head-of-ai-governance` (level 60) — board reporting, regulator engagement, budget ownership — and to `chief-ai-officer` (level 70) — AI strategy, P&L alignment

- [`02-three-lines-of-defence-for-ai-operating-model.md`](./02-three-lines-of-defence-for-ai-operating-model.md) — the operating model as a seat-and-work-product RACI composed against the mod-102 control library; classical RACI plus AI-specific `X` (external) designation; first / second / third / external seat inventory; the control-family RACI table (`AIC-DATA-*` through `AIC-IAM-*`); the pre-deployment gate and AIMS management-review artefact-level RACIs; six invariants; the two failure modes (shape-without-seats, R-equals-A collapse).
- [`03-role-descriptions-and-hiring-plan.md`](./03-role-descriptions-and-hiring-plan.md) — populating the operating model against real role packets — `ai-governance-analyst` (level 15) through `chief-ai-officer` (level 70); per-seat headcount-scaling, hire-market shape, credential bar, and hire-vs-develop-vs-cosource default; the hiring plan as a council-ratified reserved matter the head-of-AI-governance carries to the CFO; three anti-patterns (one-AI-person, consultants-for-a-year, frontier-lab-researcher-first).
- [`04-cross-audience-communications-architecture.md`](./04-cross-audience-communications-architecture.md) — the nine audiences the architect writes for (CISO, GC, CIO, CFO, CEO, audit committee, regulator, employee, customer); the document-and-audience matrix; the architecture-review-board (ARB) as the internal design-authority forum; the position-paper six-section fixed structure; four invariants and three failure modes.
- [`05-change-management-plan-for-policy-and-standard-rollouts.md`](./05-change-management-plan-for-policy-and-standard-rollouts.md) — four change classes (small / standard / major / emergency) with distinct cadences, communications shapes, training-update disciplines, and exception windows; the seven-step rollout playbook; the exception process; the training-update composition with mod-105 chapter 06; the exception-window-calibration trade-off; six invariants and three failure modes.
- [`06-certifications-portfolio-positioning.md`](./06-certifications-portfolio-positioning.md) — the four-category positioning framework (load-bearing / optional-signal / sector-specific / adjacent); the load-bearing set at level 50 (AIGP; ISO 42001 Lead Implementer where AIMS-cert ambition ≥ medium; CIPP/E or CIPP/US where personal-data processing is material); the strong-optional set (ISO 42001 Lead Auditor, ForHumanity FHCA, BABL AI, ISACA CISA / CISM / CRISC); sector-specific competence via work history (SR 11-7 for banking, FDA AI/ML for healthcare); the portfolio-composition framework and three failure modes (over-collection, under-collection, lapsed-maintenance).
- [`07-standards-community-contribution-posture.md`](./07-standards-community-contribution-posture.md) — four commitment levels (observer / member-with-attendance / active-contributor / leadership); the community-body map (ISO/IEC JTC 1/SC 42, CEN-CENELEC JTC 21, IEEE 7000-series, NIST public workshops + AISI, Frontier Model Forum, Partnership on AI, OECD.AI, adjacent bodies); the internal ratification path for representative-carried positions; five invariants and three failure modes (reactive we-don't-participate, committee tourism, solo-representative drift).
- [`08-boundary-to-head-of-ai-governance-and-chief-ai-officer.md`](./08-boundary-to-head-of-ai-governance-and-chief-ai-officer.md) — the boundary specification against the head-of-AI-governance (level 60) and chief-AI-officer (level 70); the head's five defining features (board reporting, regulator engagement, budget ownership, line management, external face); the CAO's four defining features (AI strategy, P&L alignment, executive-tier external positioning, board interface); the deliverable-boundary table (accountable / drafter / reviewer / carrier); the head's bounded emergency authority; the CAO-vs-head boundary; where the CAO seat does not exist; three failure modes (architect-encroaches-upward, head-encroaches-downward, CAO-collapses-into-head).
